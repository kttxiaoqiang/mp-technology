# PRD-006: 批量上传目录

## Problem Statement

目前知识库只支持单文件上传（通过 `<input type="file">` 一次选一个文件）和 `upload-multiple`（多文件一起选），但不能上传整个目录树。当用户需要从本地目录迁移一批文档到知识库时，需要逐个文件选择，非常低效。子目录结构也会丢失，所有文件扁平化混在一起。

## Solution

新增批量上传目录功能：用户点击「选择目录」按钮，用浏览器目录选择器选取本地文件夹，系统自动递归扫描目录下所有文件，逐个上传并自动分类。上传进度实时展示，完成后显示成功/失败统计。

## User Stories

1. 作为**管理员**，我想要选择整个本地目录上传，以便批量导入知识库文档
2. 作为**管理员**，我想要子目录中的文件也被递归上传，以便保持原有目录结构的完整性
3. 作为**管理员**，我想要上传过程中看到实时进度（第几个/共几个），以便了解当前执行状态
4. 作为**管理员**，我想要上传完成后看到成功和失败的文件列表，以便排查问题
5. 作为**管理员**，我想要同名文件自动加序号避免覆盖，以便重复上传同一目录时不会丢失旧文件
6. 作为**管理员**，我想要目录中的文件依然按关键词自动分类（方案/报告/密评FAQ/标准规范/法规政策/参考文档/其他），以便与现有文档管理规则一致

## Implementation Decisions

### 新增 API：`POST /api/upload-batch`

- 请求体：`{ "dirPath": "/path/to/directory" }`
- 服务端递归扫描目录下所有文件（`fs.readdirSync` + 递归调用 `walkDir`）
- 对每个文件：
  1. 调用 `detectCategory(filename)` 确定分类
  2. 复制文件到目标分类子目录（使用 `copyFileSync`，保留原文件）
  3. 如果目标文件名已存在，自动追加 `_1`、`_2` 序号（`while fs.existsSync()`）
  4. 调用 `autoConvertToMd()` 转换 Markdown（失败不阻断流程）
- 返回：`{ success, files: [...], count, successCount, failCount }`
- 对目录不存在的、路径不是目录的、缺参数的场景返回 400 错误
- 操作日志记录 type=batch 的上传事件

### 前端改动

**上传对话框**添加「批量上传目录」区块：
- 「📁 选择目录」按钮 → 触发隐藏的 `<input webkitdirectory multiple>` 选择器
- 选中后显示目录名和文件数量
- 「开始上传」按钮遍历所有文件，逐个调用 `POST /api/upload`（复用现有上传端点，使用 FormData）
- 实时更新进度：`上传中 3/15: xxx.docx`
- 上传完成后显示摘要：`完成！成功 14，失败 1`，并列出每个文件的上传结果
- 完成后自动刷新文件列表

**新增 CSS**：`.btn-outline` 样式（边框按钮，用于「选择目录」按钮）

### 模块变更

| 模块 | 变更 |
|------|------|
| `server.cjs` | 新增 `POST /api/upload-batch` 端点（~80 行） |
| `public/index.html` | 修改上传模态框 HTML + `_bindUpload()` 方法（批量上传交互逻辑） |

### 分页/性能考虑

- 大目录可能包含数百个文件。前端逐个串行上传，简单可靠，不涉及并发控制
- 服务端同步复制 + 转换，单个文件失败不阻断整体流程
- 文件名冲突自动加序号，不会覆写已有文件

### 与现有功能的关系

- 复用 `detectCategory`、`autoConvertToMd`、`logAction` 等现有模块
- `upload-batch` 是独立端点，不影响 `upload` 和 `upload-multiple`
- 前端上传对话框保持单文件上传不变，新增的批量上传区块使用分隔线「或」隔开

## Testing Decisions

### 测试原则

- 测试 API 的外部行为（输入 → HTTP 状态码 + 响应体），不测试内部递归逻辑的实现细节
- 每个测试独立：创建独立的知识库目录、启动独立服务器、清理
- 通过 HTTP 请求验证端到端路径：上传 → 自动分类 → 文件名去重 → 错误处理

### 测试范围

| 测试 | 优先级 |
|------|--------|
| 递归上传 4 个文件（含子目录），分类正确 | P0 |
| 重复上传同一目录，文件名自动加序号 | P0 |
| 不存在的目录返回 400 错误 | P1 |
| 空目录返回 count=0 | P1 |
| 普通文件路径（非目录）返回 400 错误 | P1 |
| 缺省 dirPath 参数返回 400 错误 | P1 |

### 测试方式

通过 Node.js `child_process.spawn` 启动独立服务实例（使用独立端口、独立知识库目录、独立数据库目录），通过 Node `http` 模块发送请求验证。测试文件位于 `test/batch-upload.test.cjs`。

## Out of Scope

- 并发上传（多个文件同时上传）。当前逐个串行上传足够
- 上传进度百分比条。文本进度已满足需求
- 拖拽上传目录。仅通过按钮选择
- 非 webkit 浏览器兼容（`webkitdirectory` 仅 Chrome/Edge/Safari 支持）。可通过 Firefox `mozdirectory` 后续扩展
- 上传前预览目录结构。用户选择目录后只显示文件数
- 暂停/取消上传。一旦开始不可中断
- 上传到特定分类子目录。依然按关键词自动分类

## Further Notes

- 前端使用 `webkitdirectory`（非标准属性）是因为这是浏览器选择目录的唯一方式，Chrome 和 Edge 均支持
- 服务端使用 `copyFileSync` 而非 `renameSync`，因为源文件可能来自不同的文件系统/挂载点
- 文件名冲突序号逻辑：从 `_1` 开始递增，只基于文件名（含扩展名）判断
